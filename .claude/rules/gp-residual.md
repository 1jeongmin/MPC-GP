# GP 잔차 모델링 룰

## 잔차의 정의 — 흔들리면 전부 무의미해진다

```
r_k = x_{k+1}^plant - f_nom_d(x_k, u_k, vx_k, kappa_k)
```

`f_nom_d`는 **MPC가 예측에 쓰는 것과 정확히 같은** RK4(`dt_ctrl`) 이산화여야 한다.
다른 dt, 다른 적분기, 다른 명목 파라미터를 쓰면 GP가 배우는 대상이 바뀐다.
잔차 계산 코드는 MPC 예측 코드와 **같은 함수를 호출**하도록 구현하라. 복사 금지.

`x_{k+1}^plant`는 `dt_ctrl`(제어 스텝) 후의 플랜트 상태다. 플랜트는 `dt_plant`로
적분되지만 잔차는 **제어 스텝 경계에서만** 취한다 (`dt_ctrl/dt_plant` = 2 스텝마다).

## 결합 형태는 이산(discrete)으로 확정 — 단위를 틀리지 마라

**`r_k`는 상태 차이이지 상태 미분이 아니다.** 단위는 `v_y` 채널이 `m/s`,
`gamma` 채널이 `rad/s`다. 연속시간 우변(`xdot`, 단위 `m/s²`·`rad/s²`)이 아니다.

따라서 GP 보정은 **RK4 바깥에서, 이산 상태 갱신식에 더한다.**

```
x_{k+1} = rk4_step(f_nom, x_k, u_k, p_k, dt_ctrl) + B_d @ mu_GP(z_k)

B_d = [[1, 0],
       [0, 1],
       [0, 0],
       [0, 0]]        # (4, 2) — v_y, gamma 행에만 주입
```

**금지 사항 (가장 흔한 버그):**

- `xdot = f_nom(x) + mu_GP(z)` 처럼 **연속 우변에 더하지 마라.** RK4 내부에서
  적분되면 보정이 `dt_ctrl`배로 축소되어 들어간다 (`dt_ctrl = 0.02` → 50배 오차).
- 이 형태를 쓰려면 학습 타깃 자체를 미분 잔차로 다시 정의해야 하는데,
  **그 경로는 채택하지 않았다.** 바꾸고 싶으면 먼저 물어라.
- GP 평가는 RK4 바깥이므로 **예측 스텝당 1회**다 (스텝당 4회가 아니다).
  `mpc-solver.md`의 비용 산정과 짝을 이룬다.

## 출력 채널

- 학습 대상은 **`v_y`, `gamma` 두 채널뿐**이다. 채널당 독립 GP 1개 (총 2개).
- `e_psi`, `e_y` 채널은 **학습하지 않는다.** 이 두 식은 `vx`, `kappa`가 정확히
  주어지면 오차 없는 기구학이므로, 잔차는 이산화 오차 수준이어야 정상이다.
  → 이 두 채널은 **검증용 진단 지표**로만 로깅한다.

**진단 임계값 (정량 기준):**

```
RMS(r_epsi), RMS(r_ey)  <=  10 * noise_floor(해당 채널)
```

`noise_floor`는 `testing.md` 게이트 5에서 측정한 RK4 vs 고정밀 적분기 차이다.
**10배를 넘으면 학습 데이터를 늘리지 말고 구현 버그를 찾아라.** 전형적 원인:

- 잔차 계산의 `kappa`, `vx`가 플랜트에 실제로 인가된 값과 다름 (프리뷰 인덱스 어긋남)
- 잔차를 `dt_ctrl`이 아닌 `dt_plant` 경계에서 취함
- `e_y_dot = v_y + v_x*e_psi`의 소각도 가정이 깨질 만큼 `e_psi`가 큼
  (이 경우는 버그가 아니라 시나리오 문제 — 초기오차를 줄이고 재확인)

이 임계값 검사는 게이트로 자동화하고, 위반 시 실행을 중단하라.

## 입력 (features)

기본: `z = [v_y, gamma, delta]` (또는 `v_y` 대신 sideslip `beta`).
`v_x`는 **시나리오 안에서 실제로 변할 때만** 추가한다.

입력 차원을 늘리기 전에 반드시 물어라. 차원이 늘면 같은 커버리지를 얻는 데
필요한 데이터가 급격히 증가하고, 그러면 "데이터 희소 영역에서 사후분산이
넓어진다"는 논문의 핵심 UQ 논증이 약해진다. **차원 최소 유지가 설계 목표다.**

## 커널·학습

- 기본 커널: ARD RBF. 다른 커널을 시도하려면 근거와 함께 제안하고 확인받아라.
- 하이퍼파라미터는 Type-II ML(Empirical Bayes)로 학습한다.
- 목적함수는 **로그 행렬식 항을 포함한 표준 NLML**
  (Rasmussen & Williams 2006, Eq. 5.8)을 구현한다.
  log-det을 생략한 축약 목적함수를 참고 코드에서 그대로 가져오지 마라.
- 입력·출력은 표준화한다. 표준화 통계(mean/std)는 모델과 **함께 저장**하고
  추론 시 재사용한다. 저장하지 않으면 재현이 깨진다.

## 사후분산은 제어에 넣지 않되, 반드시 저장한다

- 제어는 **평균 전용(mean-only, non-cautious)**이다. 분산을 제약이나 비용에
  전파하지 마라. (stochastic GP-MPC는 향후 확장으로 명시적으로 유보)
- 그러나 사후분산은 **매 스텝 계산하고 로그에 저장한다.** 이것이 EKF 대비
  차별점을 보이는 논문의 주 증거물이다. 성능 때문에 끄고 싶으면 먼저 물어라.

## CasADi 결합

```
mu(z) = k(z, Z) @ alpha          # alpha = 사전계산된 가중치 벡터
```

- `Z`(inducing/dictionary 입력), `alpha`, 하이퍼파라미터는 CasADi **파라미터**로 주입한다.
- **`M`(dictionary 크기)은 고정하고 내용만 갱신한다.** 그래야 온라인 갱신에도
  NLP 구조를 재생성하지 않는다. (제안 — `mpc-solver.md`와 짝을 이루는 결정)
- GPyTorch 등으로 학습한 결과는 `casadi_export.py`를 거쳐 순수 CasADi 표현으로
  변환한다. 제어 루프 안에서 PyTorch를 호출하지 마라.
- 변환 후 **GPyTorch 예측값과 CasADi 예측값이 일치하는지 대조 테스트**를 반드시 둔다.

## Part 2의 4개 변형은 인터페이스를 통일한다

`offline / online / online sparse / online sliding-window`는 같은 추상 인터페이스
(`fit`, `update`, `mean`, `var`, `export_casadi`)를 구현한다.
runner가 어느 변형인지 알 필요가 없어야 한다. 변형별로 runner를 분기하지 마라.

### 온라인 변형의 하이퍼파라미터 정책 (기본값 확정)

**기본: 하이퍼파라미터는 오프라인에서 한 번 학습하고 온라인에서는 고정한다.**
`update()`가 바꾸는 것은 **dictionary(`Z`)와 가중치(`alpha`)뿐**이다.

이유: 온라인 Type-II ML 재학습은 스텝당 비용이 데이터 크기에 비례해 폭증해서
Part 2의 실시간성 논증(solve time 측정)을 오염시킨다. 그리고 하이퍼파라미터가
스텝마다 흔들리면 사후분산의 시간축 비교가 무의미해진다 — 이건 논문의 주 증거물이다.

- 재학습을 켜려면 `configs/gp/*.yaml`의 `retrain_every_n_steps`(기본 `null`)로
  **명시적으로** 활성화하고, 재학습 비용을 solve time과 **분리해서** 로깅한다.
- 세 온라인 변형 모두 **같은 하이퍼파라미터 출처**를 쓴다. 변형마다 다른 값으로
  출발하면 ②③④ 비교가 성립하지 않는다.
- 표준화 통계(`mu_z`, `sd_z`, `mu_r`, `sd_r`)도 **오프라인 값으로 고정**한다.
  온라인에서 갱신하면 CasADi에 주입된 파라미터와 학습 스케일이 어긋난다.

이 정책을 바꾸려면 먼저 물어라.

## 데이터 위생

- 학습 궤적과 평가 궤적을 분리한다. 같은 주행 로그에서 학습·평가를 동시에 하지 마라.
- 데이터셋 파일에는 생성 config, git hash, seed를 함께 저장한다.
- 저마찰·슬립 구간이 없는 데이터로 학습한 GP를 슬립 구간에서 평가하는 것은
  **버그가 아니라 의도된 실험**이다(사후분산이 넓어져야 한다). 이 경우를
  "데이터가 부족하다"며 학습 데이터를 몰래 늘리지 마라.
