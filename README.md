# MPC-GP — GP 잔차 보정 기반 차량 횡방향 경로추종 MPC

명목 **선형 동역학 자전거 모델**(오차좌표계) 위에 **모델 오차 보정**을 얹은 횡방향
경로추종 MPC를 Python + CasADi로 구현하고 시뮬레이션으로 검증한다.

보정 방식 세 가지를 **완전히 동일한 조건**에서 비교한다.

| 케이스 | 보정 방식 | 불확실성의 정체 |
|---|---|---|
| `mpc_only` | 없음 (기준선) | — |
| `mpc_kf` | 외란증강 칼만필터가 외란 `d`를 **시간축**으로 추정 | `P` 대각 (aleatoric) |
| `mpc_gp` | GP가 상태→잔차 사상을 **상태공간**에서 학습 | 사후분산 (epistemic) |

핵심 논점은 "GP가 추종을 더 잘한다"가 아니라
**"GP의 불확실성은 상태공간 지도이고, KF의 것은 시간축 스칼라다"** 이다.

---

## 1. 지시받은 모델링 순서와 진행 현황

주신 4단계(state equation / 잔차 정의 / path tracking 구현 / 잔차 모델링)에 **전부
완료**로 답했다. 상세 유도·수식·구현 링크는 분리했다 — **[`MODEL.md`](MODEL.md)**.

요지만: 상태 $x=[v_y,\gamma,e_\psi,e_y]$, 잔차는 타이어 비선형성 하나로 통제,
Python(CasADi)으로 구현(MATLAB 대비 GP-NLP 결합이 자연스러워서), KF·GPR 둘 다 완료.

**현재 GP 학습 절차**(delta 시점 정합 + Type-II ML 다중 재시작)로 다시 잰 값이다.

### 이 표에서 읽어야 할 것

1. **두 보정기 모두 mpc_only 를 이긴다** — 네 시나리오 전부. 구현은 정상이다.
2. **추종오차는 전 케이스 KF 우위다.** GP 가 추종을 더 잘한다는 주장은 성립하지 않는다.
3. **NLPD 는 GP 가 4개 중 3개에서 이긴다**(①②③). 예측분포 전체의 품질에서는 GP 가 낫다.
4. **★ 그러나 외삽이 심해질수록 GP 가 무너진다.** ①에서 94.3% 였던 커버리지가
   ④에서 54.2% 로 떨어진다. KF 는 96.1% -> 79.6% 로 훨씬 완만하다.
   **논문 주장은 이 선에 맞춰야 한다** — "GP 가 낫다"가 아니라
   **"학습 분포 안에서는 GP 의 불확실성이 더 정직하다. 밖에서는 아직 아니다."**

### 개선 시도 3종 비교 (미결 #17~20)

`z_std` / `95%커버` / `RMS e_y 변화`. 전부 GP 기준선 대비이고, **제어 경로는 건드리지
않는다**(분산은 mean-only 라 제어에 안 들어간다 — 추종 변화는 GP 평균이 바뀐 결과다).

|---|---|---|---|---|

- **입력 워핑**: `a_y` 가 커지는 축(②④)에서만 듣는다. `a_y=4`(①③)에서는 학습 범위

- **이분산 잡음**: ① 에서만 개선하고 ②③ 에서 크게 악화한다. 외삽에는 틀린 처방이다

- **상태이력**: ④ 캘리브레이션은 개선하나 **추종을 +17.7% 판다**. lag1 은 더 나쁘다(+29.1%).

세 방법 모두 ④의 KF(1.786 / 79.6%)에는 못 미친다. **미결 #17 은 여전히 열려 있다.**

## 4-b. 지시사항 답변 — 7/27 대비 무엇이 바뀌었나

받은 점검 항목 7개에 대한 답이다. **전부 측정으로 답한다.**

### ① MPC 정식화에 서로 충돌하는 파라미터가 있는가 — **있었고, 제거했다**

| | 7/27 이전 | 현재 |
|---|---|---|
| `W_vy · v_y²` | 0.1 | **0.0 (제거)** |
| `R_delta · delta²` | 0.01 | **0.0 (제거)** |
| `W_gamma` | `gamma²` (절대값) | **`(gamma − v_x·kappa)²` (참조 상대)** |

**무엇이 충돌이었나**: 정상선회에서 필요한 `v_y`, `delta`, `gamma` 는 **0 이 아니라
경로가 정하는 값**이다. 그 크기를 0 으로 벌주면 목적함수가 동역학 등식제약과 **반대
방향**을 지시한다. 측정하니 `W_gamma·gamma²` 가 완벽추종 시 잔여 스테이지 비용의
**65.8%** 를 차지했고, 일정곡률에서 정상편차 `e_y` 를 3.35e-3 m 만들고 있었다
(이 항만 끄면 6.87e-4 로 감소).

**왜 gamma 만 참조 상대로 살렸나**: `gamma_ref = v_x·kappa` 는 오차 기구학
`ė_psi = gamma − v_x·kappa` 그 자체라 **차량 파라미터가 하나도 안 들어간다**
(비선형 플랜트 대비 오차 0.02%). `v_y`(−206.6%)·`delta`(+2.74%) 의 참조는 GP 가
학습할 대상인 선형모델에서 나오므로, 참조로 쓰면 모델오차를 목적함수에 **두 번째
경로로** 들여오게 된다.

**제거로 안전장치가 사라지지 않았다** — 세 시나리오에서 추종·전륜슬립·조향포화가
**동시에** 개선됐다(예: ay6 에서 RMS `e_y` 2.945e-2→2.473e-2, max|α_f| 6.858°→6.413°,
rate 포화 23.3%→16.2%). 각 물리적 관심사는 이미 옳은 구조가 맡고 있다:
전륜 포화는 하드제약 `|delta|≤delta_max`, 평활은 `R_ddelta`(변화율 항).

**현재 남은 충돌: 없다.** 다만 `R_ddelta` 가 raw 차분을 벌줘 유효 가중이
`R_ddelta·dt_ctrl²` 라는 점은 `configs/mpc/default.yaml` 에 TODO 로 남겨 뒀다.

### ② 최소화 텀이 `상태=0` 인가 `레퍼런스−상태=0` 인가 — **절대 크기 페널티는 하나도 없다**

| 항 | 형태 | 근거 |
|---|---|---|
| `e_y`, `e_psi` | **오차좌표계** — 상태 자체가 이미 "레퍼런스 − 실제" | 0 으로 보내는 것이 곧 추종 |
| `gamma` | **레퍼런스 상대** `(gamma − v_x·kappa)²` | 참조가 순수 기구학 (오차 0.02%) |
| `v_y`, `delta` | **없음(0)** | 믿을 만한 참조가 없어서 항 자체를 제거 |
| `Δdelta` | 변화율 | 정상상태에서 0 — 구조가 옳은 유일한 입력 항 |
| 종단 | `e_y`, `e_psi` 만 | 오차좌표계 |

즉 **`x_ref`, `u_ref` 를 따로 만들지 않는다.** `kappa` 프리뷰가 지평에 채워지면 MPC 가
필요한 요레이트를 스스로 만든다. 구현: `mpc_base.py` 의 `gamma_ref = p_vx[k]*p_kappa[k]`
— 이미 `P` 에 있는 프리뷰를 재사용하므로 새 파라미터도 NLP 재빌드도 없다.

  평균과 최악이 반대 방향이다. 짧은 지평이 더 공격적으로 반응한다.
- 7/30 측정(N=30→60 에서 세 경로 모두 악화)과 **같은 방향**이다. 그 사이 입력
  블로킹·warm start 가 들어갔지만 결론은 바뀌지 않았다.

**결론: 지평의 근거는 추종오차가 아니라 제약 예견·안정성 여유여야 한다.**
현재 N=50 유지. 넓히려면 그 근거를 따로 세워야 한다.

### ④ GP 계산 속도 — **예산 안에 여유 있다**

M=2000, `dt_ctrl` = 20 ms. `solve_time` 은 IPOPT 구간만 재므로 **GP 평가는 별도로 더한다**
(`mpc_base.solve` 의 타이머가 `set_operating_point` 뒤에서 시작한다).

| 특징 | d | mu (CasADi) | Var[f*] | GP 합계 | + solve | **총합** |
|---|---|---|---|---|---|---|
| 기준선 | 3 | 1.07 ms | 2.47 ms | **3.54 ms** | 9.7 ms | ~13.3 ms |
| delta이력 lag2 | 5 | 2.15 | 2.75 | 4.90 (1.39x) | 9.2 | ~14.1 ms |
| 상태이력 lag1 | 6 | 2.14 | 2.64 | 4.78 (1.35x) | 11.2 | ~16.0 ms |
| 상태이력 lag2 | 9 | 2.58 | 2.88 | 5.46 (1.54x) | 9.1 | ~14.6 ms |

- **`M` 은 solve time 과 무관하다** — GP 평균은 solve 당 1회 평가돼 파라미터 2개로만
  주입된다(지평 상수 결합). 커지는 것은 학습 O(M³), 스텝당 분산 O(M²) 뿐이다.
- 분산 계산(2.5~2.9 ms)이 평균(1.1~2.6 ms)보다 비싸다. 분산은 **제어에 쓰지 않지만**
  논문의 주 증거물이라 매 스텝 계산·저장한다(`gp-residual.md`).
- 수렴 실패 0%, dt 초과 0.04~0.3%.

### ⑤ GP 분산 영역 그래프 — **다시 그렸다**

`scripts/plot_gp_variance_report.py` → `results/figures_gp_variance/` (시나리오당 2장).

1. `*_band.png` — GP 평균 ± 95% 예측구간(음영) + 실측 잔차. **관측 예측분산
   `Var[y*] = Var[f*] + sigma_n²`** 를 쓴다(비교 대상이 관측된 잔차이므로).
2. `*_split.png` — **불확실성 분해**(신규). `Var[f*]`(epistemic, "여기 데이터가
   있었나")와 `sigma_n²`(aleatoric, "원래 튀는 양")을 나눠 보여준다. 뭉쳐 그리면
   "낯설어서 모르는 것"과 "원래 잡음이 큰 곳"을 구별할 수 없다.

```

  ④ rtf_ay6 (OOD)     : 76.3%   <- GP 가 낯섦을 느끼고 있긴 하다
```

### ⑥⑦ GP 커널 입력에 과거를 넣기 — **2시점 vs 3시점, 성능 vs 속도**

`b_k = [v_y_k, gamma_k, delta_{k−1}]` 을 한 시점 블록으로 두고 과거를 이어 붙였다.
(`delta_k` 는 solve 전이라 배포가 알 수 없어서 쓸 수 없다 — 인과성.)

**개루프 홀드아웃**(랩 블록 분할, M=2000):

| 변형 | d | NLPD | 기준선 대비 | GP 시간 |
|---|---|---|---|---|
| 기준선 (현재만) | 3 | −6.048 | — | 3.54 ms |
| **2시점 (lag1)** | 6 | −6.532 | **−8.0%** | 4.78 ms (1.35x) |
| **3시점 (lag2)** | 9 | **−6.749** | **−11.6%** | 5.46 ms (1.54x) |
| delta 이력만 lag2 | 5 | −6.059 | −0.2% | 4.90 ms |

**폐루프**:

| 시나리오 | 기준선 | 2시점(lag1) | 3시점(lag2) |
|---|---|---|---|
| ① lpf_ay4 NLPD | −5.87 | −6.40 | **−6.64** |
| ① 추종 | 8.9241e-3 | 8.9149e-3 | **8.8992e-3** |
| ④ rtf_ay6 커버 | 54.2% | 53.3% | **61.2%** |
| ④ 추종 | 3.2915e-2 | **4.2508e-2 (+29.1%)** | 3.8734e-2 (+17.7%) |

**답 — 고른다면 3시점(lag2)이다.** 2시점보다 개루프·폐루프 **양쪽에서 낫고**
속도 차이는 0.68 ms(전체 예산의 3.4%)뿐이다. 2시점은 OOD 추종이 +29.1% 로 오히려
3시점보다 나쁘다 — 중간 지점이 최악인 셈이라 "싸게 절반만 얻기"가 안 된다.

**다만 둘 다 권하지 않는다.** OOD 캘리브레이션 개선폭이 입력 워핑과 비슷한데
(61.2% vs 65.0%) **추종 대가가 7배 비싸다**(+17.7% vs +2.5%). 그리고 차원을 3→9 로
늘리는 것은 `gp-residual.md` 「차원 최소 유지가 설계 목표」와 정면으로 충돌한다 —
데이터 희소 영역에서 사후분산이 넓어진다는 **논문의 핵심 UQ 논증을 약하게 만든다.**

**delta 이력만 늘리는 것은 무효다**(−0.2% = 잡음 수준). (추측) `R_ddelta` 로 조향이
매끄러워 `delta_{k−2,3}` 이 `delta_{k−1}` 과 거의 중복 정보이기 때문으로 보인다.

### 설계의 중심 — `StepModel` 주입

세 케이스가 `if`문 없이 갈리는 이유가 여기 있다. **`MpcBase`는 어떤 케이스인지 모른다.**

```python
class StepModel(Protocol):
    extra_param_dim: int
    def step_sym(self, x, u, vx, kappa, p_extra): ...   # 이산 1스텝 전이
    def extra_param_values(self) -> np.ndarray: ...
```

| 구현체 | 이산 전이 | 결합 위치 |
|---|---|---|
| `NominalStepModel` | $\mathrm{rk4}(f_{nom})$ | — |
| `DisturbanceStepModel` (KF) | $\mathrm{rk4}(f_{nom}+B_c d)$ | RK4 **안** ($d$는 rate) |
| `GPStepModel` (GP) | $\mathrm{rk4}(f_{nom})+B_d\hat\mu$ | RK4 **밖** ($r$은 상태차이) |

케이스 선택도 문자열 분기가 아니라 **참조된 config 그룹**으로 한다
([`src/sim/assemble.py`](src/sim/assemble.py)) — `gp` 그룹이 있으면 GP 케이스,
`ekf`가 있으면 KF, 둘 다 없으면 명목. 새 케이스 추가 = 레지스트리 한 줄.

## 9. 알려진 한계

정직하게 적어 둔다.

- **센서 잡음 값은 특정 논문 수치가 아니라 센서 등급별 통상값 기준의 공학적 추정치**다.
  문헌 인용이 필요하면 실제 데이터시트로 대체해야 한다.
- $v_y$를 직접 측정한다고 가정했다. **양산차에는 $v_y$를 직접 재는 센서가 없다.**
  부분관측이 KF를 악화시키는 것을 확인한 뒤, 이 연구의 초점이 상태추정이 아니라
  모델오차 처리이므로 전상태 측정으로 통제한 결과다.
- Fiala 모델의 큐빅 형태는 여러 문헌에서 동일하게 확인되지만 **원 출처 DOI는 확인하지 못했다.**
  다만 선형 극한·포화·원점 대칭 성질은 수치미분으로 자체 검증했다.
- `limo` 차량 파라미터는 전부 미검증 추정치다(YAML의 `TODO` 주석 참조).
- GP는 mean-only(non-cautious)다. 분산을 제어에 전파하는 stochastic MPC는 이번 스코프 밖이다.
- **(해소됨) 잡음 시나리오 조향 rate 포화 ~47%** — 옛 결과(§4)에서는 세 케이스 모두
  필터링 안 된 생측정값을 제어 피드백으로 받아 발생했다. 2026-07-30 공통
  상태추정기(잡음 낀 측정을 명목 4상태 KF 로 걸러 세 케이스 모두 동일하게 피드백)
  도입으로 0%로 해소, 지금은 기본 구성이다. 그 병합으로 무효화됐던 §4 수치는
  2026-08-03 에 전면 재측정해 갱신했다.
- **★ 외삽에서 GP 의 불확실성이 무너진다 (미해결).** in-distribution 에서 95%커버
  94.3% 이던 것이 형상+강도 외삽에서 54.2% 로 떨어진다(KF 는 96.1%→79.6%).
  원인은 규명됐다 — 정상(stationary) 커널은 lengthscale 하나가 "함수의 매끄러움"과
  "얼마나 멀어져야 모른다고 할지"를 **동시에** 정해서, 평균이 매끄러우면 멀리까지
  자신만만해진다(실측: 평가점이 학습 범위 밖 38.6% 인데 ARD 최근접거리 중앙값 0.96).
  입력 워핑으로 54.2%→65.0% 까지 올렸으나 KF 수준에는 못 미친다. `handoff.md` 미결 #17.
- **잔차를 타이어 비선형성 하나로 통제한 것은 실차 잔차를 대표하지 않는다.** 확인해 본
  GP-MPC 문헌(Hewing et al. arXiv:1705.10702, GP-based overtaking MPC 2021)은 대부분
  잔차를 "model mismatch and unmodeled dynamics"로 뭉뚱그려 학습시키지, 물리 원인
  하나로 좁히지 않는다. 이 프로젝트의 단일원인 통제는 인과관계를 깨끗하게 검증하기
  위한 의도적 선택이며, combined slip·하중이동·액추에이터 지연·파라미터 불확실성 등
  실차에서 섞여 들어올 다른 잔차원은 다루지 않는다.
